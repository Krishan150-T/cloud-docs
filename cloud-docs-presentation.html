01 · The problem

What does a full-stack application need?

Our application is more than frontend + backend. Once we deploy it to the cloud, we need infrastructure for every part of the system.

Compute

Where do our application containers actually run?

Database

Where do we persist users, documents and application metadata?

File Storage

Where do uploaded files live independently of containers?

Networking

How do users reach the application while keeping internal resources private?

Security

Which service or application component is allowed to access which resource?

Observability

How do we inspect application logs and determine whether services are healthy?

AWS gives us managed services for these individual responsibilities — and our POC demonstrates how they work together.

Why this design?

Only the ALB is exposed as the public entry point.

ECS tasks do not receive public IP addresses.

RDS is not publicly accessible.

Security groups control which layer can communicate with the next layer.

ECS

Elastic Container Service

Manages the deployment and lifecycle of our containerized frontend and backend services.

F

Fargate

Runs the ECS tasks without requiring us to provision or manage EC2 servers for the container workload.

ECR

Elastic Container Registry

Stores the Docker images that ECS pulls when launching our tasks.

ALB

Load Balancer

Routes incoming traffic to the appropriate ECS target group and performs health checks.

05 · Data layer

RDS for metadata. S3 for files.

DB

Amazon RDS · PostgreSQL

Stores:

  • Application data
  • Document metadata
  • S3 object keys / references

RDS gives us managed PostgreSQL rather than tying database persistence to an ECS container.

S3

Amazon S3

Stores:

  • Actual uploaded documents
  • Objects independent of ECS task lifecycle

The bucket remains private; the backend controls access.

Upload → Backend → S3: actual file
          ↘ RDS: metadata + S3 key
ECS storage is ephemeral. S3 gives the uploaded files durable storage outside the container lifecycle.
RDS = STRUCTURED DATA · S3 = OBJECT STORAGE06 / 08
06 · Security & observability

Who can access what — and how do we know it's working?

IAM

IAM Roles

The ECS execution role lets ECS pull images, write logs and retrieve configured secrets.

The ECS task role gives application code runtime permissions such as S3 access.

SM

Secrets Manager

Database credentials are managed securely rather than being hardcoded into the application configuration.

SG

Security Groups

Traffic is restricted between layers: ALB → ECS → RDS. RDS accepts PostgreSQL traffic only from the intended application layer.

CW

CloudWatch

Frontend and backend container logs are collected here for monitoring, debugging and troubleshooting.
